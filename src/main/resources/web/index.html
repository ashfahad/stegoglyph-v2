Inside StegoGlyph

A practical look at the Unicode format, processing flow and security boundaries.

03 / ABOUT
01

Choose a carrier

A visible emoji or text prefix is placed before the encoded payload. It provides a carrier appearance, not visual embedding inside the emoji's glyph.

02

Convert to Unicode

The message is converted to UTF-8. Each byte is split into two four-bit values and represented using Unicode variation selectors.

03

Verify on decode

Invisible framing markers identify the payload boundaries. The decoder reconstructs bytes, checks the checksum and strictly decodes UTF-8.

Payload structure

The current format places a visible carrier prefix before an invisible framed sequence. The message bytes and one checksum byte are represented by variation selectors U+FE00 through U+FE0F.

Carrier prefix→ U+2062 start→ Message selectors→ Checksum→ U+2063 end
Important: steganography is not encryption

StegoGlyph provides visual concealment using Unicode characters and a basic non-cryptographic checksum for accidental-corruption detection. It does not encrypt the message, provide confidentiality or authenticate its sender. Anyone who knows the format can decode it. Do not use it to protect sensitive information.

Compatibility and limitations

Some messaging platforms, editors or text-processing systems may remove, normalize or alter default-ignorable Unicode characters. A payload that works in one application may not survive copy-and-paste through another.

The visible carrier is a prefix followed by the hidden Unicode payload. The message is not embedded into the visual shape of the emoji. The checksum detects some accidental changes but is not collision-resistant or cryptographically secure.
